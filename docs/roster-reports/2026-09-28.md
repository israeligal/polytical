## D. SKILL CHECK — `caricature-cards/SKILL.md`

Reviewed the skill against current tooling and endpoints. No hard breakage found.

**Observations:**

1. **Photo sources** — Wikipedia `pageimages` API and `query.wikidata.org` SPARQL are both stable public endpoints. No change needed.

2. **`mcp__claude-in-chrome__file_upload`** — The tool name uses the `mcp__` prefix convention, which is correct. However, the exact MCP server name (`claude-in-chrome`) could differ across sessions depending on how the server is configured. The SKILL already calls this out as an *alternative* ("frees the input side") rather than the primary path, so it won't break the pipeline if the tool is unavailable.

3. **Gemini UI** — The caution about "Gemini window resizes between sessions — re-find New-chat/input/send from a screenshot" is still valid; Gemini's web UI continues to evolve. No update needed.

4. **`osascript` clipboard** — macOS-only, unchanged. Valid for the described use case.

5. **Generation-date tracking gap** — SKILL.md has no mechanism for recording *when* a card was generated. This run had to flag "verify frame — appointment post-dates likely card generation" rather than giving a definitive answer. 

   **Suggested addition** (append to `## Files` section):
   ```
   `.caricature-capture/card-log.jsonl` (gitignored) — one line per generated card:
   {"personId": 30847, "generatedAt": "2025-01-15", "tier": "common"}
   Reading the log lets future roster checks flag tier changes with certainty.
   ```
